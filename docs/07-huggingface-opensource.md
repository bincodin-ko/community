# 07. 허깅페이스 오픈소스 — 온다에 바로 쓸 수 있는 것

> 조사 한계: 이 환경에서 huggingface.co 직접 접근이 차단되어 모델 카드 원문은 못 봤다. 아래는 검색 결과·GitHub·논문으로 확인한 것이며, **사용 전 각 모델 카드의 라이선스·최신 버전을 반드시 확인**해야 한다.

## 2. 라벨 주의점 (게이 커뮤니티 특수성)

- 범용 혐오 분류기는 **성소수자 관련 단어 자체를 혐오로 오탐**하기 쉽다(피해자의 자기 서술에 "게이", "호모" 같은 단어가 많다). UnSmile 계열도 예외가 아니다. → **자동 삭제 금지, 자동 "검토 대기"만**. 임계치는 우리 글로 재보정.
- "아웃팅(신상 노출)"은 혐오 분류기가 잡는 범주가 아니다. → 규칙 기반(전화번호·이메일·학교/회사명·SNS 핸들 패턴) + Jev Noul("이 글은 특정인을 식별할 수 있는 정보를 담고 있다") 조합(`docs/08`).
- 위기(자해·자살) 감지용 공개 한국어 모델은 **찾지 못했다**(학술 연구는 설문 데이터 기반이라 텍스트 분류기가 아님). → 키워드 + Jev Noul + 상담 연락처 노출로 대체. 진단이 아니라 "연락처를 보여줄지"만 결정한다.

## 3. 추천 구성 (v0.2 기준)

```
글/댓글 제출
  ├─ (브라우저) Transformers.js 소형 분류기 → "신상/혐오 가능성" 경고만, 차단 없음
  ├─ (서버) 규칙: 전화·이메일·URL·핸들 패턴 → 즉시 검토 대기
  ├─ (서버) Jev: block?/category/crisis?/topic  (docs/08)
  └─ (서버, 선택) kor_unsmile 분류기 → 성소수자 혐오 확률을 Jev 결과와 교차 → 검토 큐 우선순위
저장 후
  └─ KURE-v1 임베딩 → "비슷한 이야기" 3개 추천, 중복·도배 감지
주간
  └─ kanana-nano로 다이제스트 초안 → 운영자 검토 → 발송
```

## 4. Jev의 오픈소스 대체재 (허깅페이스·GitHub)

Jev는 폐쇄 모델이고 대기열이 있다. 같은 "타입 결정" 패턴을 오픈으로 재현한 것들:

| 프로젝트 | 내용 | 비고 |
|---|---|---|
| `scienthoon/luce` | 문장으로 결정 과제를 쓰면 LLM 교사가 학습 데이터를 만들고, Qwen3-4B-Base + LoRA + 결정 헤드가 한 번의 forward로 보정된 확률을 낸다. 12GB GPU에서 학습 | 티켓 91.1 vs Jev 75.1 등 자체 보고. 검증 필요 |
| `Heman10x-NGU/openJev-verdict-2.0` | 151M 비자기회귀 결정 모델 | 자체 벤치 주장 |
| `vinnylarouge/jevlike` | 옵션 목록 중 선택 확률을 한 번에 내는 소형 모델 학습 라이브러리 | — |
| `zhihz/openjev` | 이중언어 확률 질문 로컬 프리뷰 | 연구용 |

**판단**: 초기에는 Jev(또는 OpenRouter 경유)로 시작하고, 우리 글로 라벨이 500개쯤 쌓이면 Luce 방식으로 자체 결정 모델을 학습해 벤더 의존을 없애는 것이 현실적이다.

## 5. 하지 말 것
- 범용 LLM에게 "이 글이 혐오인가?"를 자유 텍스트로 묻고 파싱하기 — 느리고, 적대적 입력에서 파싱 실패로 fail-open된다(Mastra 사례).
- 임베딩으로 "성향 유사 사용자 매칭" — 온다는 만남 앱이 아니다. 임베딩은 **글 ↔ 글**에만 쓴다.
- 사용자 글을 외부 API에 보낼 때 닉네임·ID를 함께 보내기 — 본문만, 익명화해서.
