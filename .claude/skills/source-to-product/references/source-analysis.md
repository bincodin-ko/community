# 소스 분석 — 인터뷰·영상·남의 제품에서 무엇을 뽑아내나

## 먼저: 누가 누구인가

제목에 이름이 하나 있으면 그건 대개 **말하는 사람**이다. 만든 사람은 안쪽에 있다.

| 역할 | 확인 방법 |
|---|---|
| 호스트·인터뷰어 | 채널 주인, "welcome to my podcast", 질문하는 쪽 |
| 게스트·창업자 | "founder of ○○", 자기 제품 이야기를 하는 쪽 |

둘을 섞으면 분석 전체가 엉뚱한 사람을 향한다. 확신이 없으면 사용자에게 한 줄로 묻는다. 나중에 전부 다시 쓰는 것보다 싸다.

## 원문 접근이 막혔을 때

영상·팟캐스트·SNS 본문은 차단되는 환경이 흔하다. 순서:

1. **사용자에게 전사를 요청한다.** "전사나 자막을 주시면 정확히 분석하겠습니다." 대부분 바로 준다.
2. 받기 전에는 검색 결과로 재구성하되 **문서 맨 위에 "원문 미확보"를 적는다.**
3. 전사를 받으면 **버리고 다시 쓴다.** 추정을 수정하는 방식은 추정의 틀을 남긴다.

전사를 받으면 **타임코드를 인용한다.** `(13:23~16:42)` 같은 표기는 나중에 검증 가능하게 만들고, 당신이 실제로 읽었다는 증거다.

## 인물에서 뽑을 것

서사의 구조를 뽑는다. 감동적인 문장이 아니라 **전환의 메커니즘**이다.

1. 결핍 — 무엇이 없었나
2. 잘못된 해결책 — 무엇으로 그걸 메웠고, 그 대가는 무엇이었나
3. 붕괴 — 언제 무너졌나
4. **전환** — 어떤 생각이 바뀌었나. 한 문장으로 쓸 수 있어야 한다
5. 사명 — 그래서 지금 무엇을 하나

4번이 제품의 핵심 가치다. 나머지는 맥락이다.

## 제품에서 뽑을 것

인물 분석에서 멈추면 안 된다. 사용자가 만들려는 건 제품이다.

| 항목 | 구체적으로 무엇을 찾나 |
|---|---|
| **만들게 된 계기** | 전사에서 직접 말한 대목. 추측 금지 |
| **무엇으로 만들었나** | 직접 개발 / 플랫폼 임대(Skool·Discord·Substack 등) / 노코드. **비율이 중요하다** — 대부분은 임대다 |
| **수익 구조** | 가격, 티어, 무엇이 무료고 무엇이 유료인가 |
| **초기 고객 확보** | 첫 100명이 어디서 왔나. 숏폼? 검색? 기존 청중? |
| **리추얼** | 반복되는 일정(주간 콜, 뉴스레터). 소속감의 실체다 |
| **어려움** | 플랫폼 정지, 1인 한계, 번아웃, 내부 갈등 |
| **한계** | 그가 못 하는 것 = 당신의 기회 |

**"직접 개발이 정당화되는가"를 반드시 따진다.** 원본이 플랫폼을 임대해 만들었다면, 당신이 직접 만드는 이유가 있어야 한다. 그 이유(완전 익명, 자국어 안전, 검색 가능한 아카이브, 플랫폼 독립)를 못 대면 직접 만들지 말고 임대하는 게 맞다.

## 다른 맥락으로 옮기기

소스가 다른 나라면 **압력 구조를 매핑한다.** 표로 만든다.

```
| 원본의 압력        | 우리 맥락의 대응물  |
|-------------------|-------------------|
| 종교 교리          | 가족 규범·결혼 압박 |
| 커뮤니티 = 교회     | 커뮤니티 = ○○      |
```

그대로 번역되지 않는 것이 반드시 있다. 원본의 해법이 **재현 불가능한 조건**(그 사람의 체격, 그 사람의 청중, 그 나라의 법)에 기대고 있으면, **원리만 가져오고 수단은 바꾼다.**

## 논쟁 지점을 적는다

원본 인물이 자기 커뮤니티 안에서 논쟁적인 위치라면 그것도 적는다. 그 포지셔닝이 성장의 엔진이자 분열의 원인인 경우가 많다. 당신의 제품이 그 분열까지 수입할 필요는 없다.
