# 허깅페이스 오픈소스 조사

직접 모델을 만들거나 상용 API에 전부 맡기기 전에, **이미 누가 만들어 둔 게 있는지 먼저 본다.** 특히 한국어는 분류·임베딩·소형 LLM 모두 공개된 게 많다.

## 조사 순서

### 1. 제품 문제를 모델 과제로 번역한다

"혐오 댓글을 막고 싶다"는 모델 과제가 아니다. 이렇게 쪼갠다.

| 제품 문제 | 모델 과제 | 찾을 것 |
|---|---|---|
| 혐오·괴롭힘 차단 | text-classification | 한국어 혐오 분류, 라벨 구성 |
| "비슷한 글" 추천, 중복 감지 | sentence-similarity | 한국어 임베딩, 리랭커 |
| 초안 생성 | text-generation | 소형 한국어 LLM(2B 이하) |
| 브라우저에서 사전 경고 | ONNX + transformers.js | 양자화된 소형 분류기 |

과제 이름(pipeline tag)을 정해야 검색이 된다.

### 2. 데이터셋에서 모델로 역추적한다

**모델 이름보다 데이터셋 이름이 검색에 유리하다.** 좋은 한국어 데이터셋은 그걸로 학습된 모델들을 달고 다닌다.

허깅페이스에서 `dataset:<데이터셋이름>` 필터로 그 데이터로 학습된 모델 목록을 볼 수 있다.

한국어에서 출발점이 되는 데이터셋:
- 혐오 표현: `smilegate-ai/kor_unsmile` (10개 라벨 — 여성/가족, 남성, **성소수자**, 인종/국적, 연령, 지역, 종교, 기타혐오, 악플/욕설, clean), `jeanlee/kmhas_korean_hate_speech` (K-MHaS, 10만+ 문장, 다중 라벨)
- 검색·임베딩: KURE, BGE-m3 한국어 파인튜닝 계열

**라벨 구성을 반드시 확인한다.** 당신의 제품에 필요한 라벨이 그 데이터셋에 있는지가 핵심이다. 없으면 그 모델은 당신 문제를 못 푼다.

### 3. 라이선스와 최신성을 확인한다

모델 카드에서 확인할 것:
- **라이선스** — 상업적 사용 가능한가. CC-BY-NC 계열이면 제품에 못 쓴다
- **마지막 업데이트** — 2년 넘게 멈춘 모델은 후보에서 내린다
- **평가 지표** — 저자가 어떤 데이터로 재고 얼마가 나왔는지. 없으면 당신이 재야 한다
- **모델 크기** — 서빙 비용을 정한다. 2B 이하는 CPU·저가 GPU에서 돈다

### 4. 접근이 막히면 정직하게 적는다

`huggingface.co` 가 차단된 환경이 있다. 그때는 검색으로 모은 정보만으로 후보를 적고, **"모델 카드 원문 미확인, 라이선스·최신 버전을 반드시 직접 확인할 것"**이라고 문서에 쓴다. 확인 못 한 것을 확인한 것처럼 쓰지 않는다.

## 한국어 분류기의 함정

**범용 혐오 분류기는 성소수자·여성·소수자 관련 단어 자체를 혐오로 오탐한다.** 피해자가 자기 경험을 서술하는 글에 그 단어가 가장 많이 등장하기 때문이다.

그래서:
- **자동 삭제에 쓰지 않는다.** "검토 대기"로만 보낸다
- 임계치는 **당신의 글**로 재보정한다. 저자가 발표한 F1은 저자의 데이터에서의 숫자다
- **어려운 음성 사례**(차단하면 안 되는 글)를 라벨 데이터에 반드시 넣는다. 그게 없으면 오탐을 못 잰다

## 상용 판정 모델과 조합하기

오픈소스 분류기를 **1차 결정자**로 쓰지 말고 **2차 의견**으로 쓰는 구성이 안전하다.

```
규칙(정규식)      → 항상 동작. 벤더 장애와 무관
판정 모델         → 1차 결정 (차단/검토/통과)
오픈소스 분류기    → 2차 의견. 검토 큐 우선순위와 교차 확인
```

이렇게 두면 오픈소스 모델을 교체하거나 빼도 제품이 멈추지 않는다.

## 자체 서빙

작은 분류기는 FastAPI + transformers 파이프라인 20줄이면 뜬다. 앱은 HTTP 로만 부르고, **환경변수가 없으면 이 층을 통째로 건너뛰도록** 만든다. 그래야 개발·CI에서 모델 없이 돌아간다.

## 벤더 의존을 줄이는 경로

상용 판정 모델로 시작하되, 당신의 글로 라벨이 수백 건 쌓이면 **같은 결정 과제를 작은 오픈 모델로 학습**하는 선택지가 생긴다. 소형 베이스 모델 + LoRA + 결정 헤드로 보정된 확률을 내는 공개 레시피들이 있다. 처음부터 할 일은 아니지만, **라벨을 모아두면 나중에 가능해진다**는 걸 알고 라벨을 모은다.
